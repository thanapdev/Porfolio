# Portfolio Site: Design Spec

Date: 2026-10-21
Owner: Thanapong Yamkamol (GitHub `thanapdev`)
Status: approved in chat; awaiting written-spec review

## 1. Goal and audience

This is a personal portfolio site for a student UX/UI designer who also writes code. It serves two uses: getting freelance work and applying for UX/UI jobs.

- **Readers:** HR, hiring managers and freelance clients. Many will skim for 30 seconds.
- **Pitch:** "a designer who builds real things you can touch and play with."
- **Mood:** playful, with small interactions people want to try, but clear and professional.
- **Visual source of truth:** `mockup-full.html` (approved). The real site must match its look and behavior.
- **Structure reference:** whyramachandran.design, for section order only. Do not copy its look.

### Success criteria

- An HR reader can find who the owner is, what they do, the two case studies and how to make contact without using any toy.
- The site works on mobile and desktop, with or without JavaScript for reading.
- Lighthouse scores 90 or higher for Performance, Accessibility and SEO on the home page (mobile).
- Pushing to `main` deploys the site on Vercel with no manual step.

## 2. Scope

### In scope (v1)

- Home page with Hero, Work, About + Skills, Timeline and Contact.
- One case study page per project: Yee-Peng-CNX and The Reborn Gacha.
- 404 page.
- English only.

### Out of scope (v1)

- Thai language. The file structure must not block adding it later.
- CMS. Content lives in MDX in the repo.
- Contact form. Contact uses `mailto:`.
- Dark mode, analytics and a custom domain. The site uses `*.vercel.app` for now.

## 3. Stack

- **Framework:** Next.js with the App Router and TypeScript.
- **Content:** MDX via `@next/mdx`, with frontmatter parsed by `gray-matter`.
- **Styling:** global design tokens in `app/globals.css` plus CSS Modules per component. No Tailwind and no UI library.
- **Fonts:** `next/font/google` (self-hosted at build time).
  - Bricolage Grotesque: display.
  - Space Grotesk: body.
  - Caveat: handwriting.
  - Fredoka: buttons.
  - Noto Sans Thai: fallback.
- **Animation:** CSS transitions and the Web Animations API. No animation library.
- **Tests:** Vitest for unit tests. Playwright with `@axe-core/playwright` for E2E and accessibility.
- **Hosting:** Vercel. Every page is statically generated.

Why this stack: the mockup's hand-made style (tape, tilt, hard shadows) is plain CSS and ports directly to CSS Modules. The site has no server needs, so static output is the simplest and fastest choice.

## 4. Routes

| Route | Content |
|---|---|
| `/` | Home: Hero, Work, About, Timeline, Contact. Matches `mockup-full.html`. |
| `/work/[slug]` | Case study. Slugs come from `content/work/*.mdx`. Built with `generateStaticParams`. |
| `not-found` | Paper-style 404: "Lost? This page got reborn somewhere else." plus a button home. |

## 6. Content model

Each `content/work/<slug>.mdx` file starts with this frontmatter.

| Field | Type | Required | Notes |
|---|---|---|---|
| `title` | string | yes | |
| `year` | number | yes | |
| `role` | string | yes | Yee-Peng-CNX: "Experience Designer". Follow the repo README. |
| `team` | string | yes | For example "team of 2" or "solo". |
| `tags` | string[] | yes | 1–3 short uppercase tags. |
| `summary` | string | yes | Card blurb, at most 2 sentences. |
| `tldr` | `{problem, did, result}` | yes | Shown as 3 sticky notes. |
| `metric` | `{value, label}` | yes | Shown on the home card's sticky note. |
| `cover`, `coverAlt` | string | yes | Build fails if `coverAlt` is missing. |
| `live`, `repo` | URL | no | A button shows only when the URL is present. |
| `order` | number | yes | Sort order on the home page. |

- `lib/projects.ts` reads every MDX file and checks that each required field is present and has the right type. A missing or invalid field throws, which stops the build and names the file and the field.
- `readTime` is computed from the word count at 200 words per minute, rounded up. It is never written by hand.
- `lib/timeline-extra.ts` holds rows that have no case study, with the same `title`, `year`, `role` and link fields. The timeline merges both sources and sorts them by year, newest first.

## 7. Home page

The home page ports `mockup-full.html` section by section. The behavior below is required.

- **Nav:** sticky. Below 700px it collapses to a "Menu" button with `aria-expanded`. Choosing a link closes the menu.
- **Hero:** the name is split into letter spans, with each word kept together so a word never breaks across lines. Clicking a letter makes it pop.
  - Below 760px, the sticker zone stacks under the text.
- **StickerZone:** four stickers plus the ControlPanel, all draggable with pointer events.
  - A sticker cannot be dragged outside the zone.
  - A focused sticker moves 12px per arrow key press.
  - Sticker positions are not saved.
- **ControlPanel:** drags by its grip only, so the controls inside stay usable.
  - **Design/Code switch** (`role="switch"`): sets the name to `<Thanapong />`, changes the role line and tints the paper. The mode resets on reload.
  - **Wobble slider:** sets `--play` (0–1), which controls letter tilt and the amount of confetti.
  - **"Don't press" button:** fires confetti and changes its own label.
- **ProjectCard:** taped card. On hover or `:focus-within` it straightens and lifts. The image side alternates left and right on desktop.
- **SkillChip:** a button with `aria-pressed` that flips to show tools on the back.
- **Timeline:** a table on desktop. Below 700px it becomes a stacked list with inline labels.
- **Contact:** a big heading plus 3D buttons for Email (`mailto:t.yamkamol.work@gmail.com`), LinkedIn, Resume (`/resume.pdf`) and GitHub.

All toys are client components. Everything else is a server component. With JavaScript off, all text and links still work. Only the toys stop.

## 8. Case study page

The page uses the same paper style as the home page, in this order:

1. **Header:** title, tags, year, role, team, read time, and Live / Repo buttons.
2. **Cover:** a polaroid-framed image with tape.
3. **TL;DR:** three sticky notes for Problem, What I did and Result.
4. **MDX body:** recommended order is Problem, Research, Ideas, Design, Build, Result, What I learned. Sections may be skipped.
5. **Footer:** "Next project →" (wraps around to the first project) and "Back to all work".

MDX components (keep the set small):

- `<StickyNote>`: a key number or quote.
- `<Polaroid src alt caption>`: an image with a handwritten caption.
- `<BeforeAfter before after alt>`: a slider that compares two images. It responds to drag, and the handle is a `role="slider"` that moves with the arrow keys.
- `<Callout>`: a highlighted aside.

## 9. Placeholders

- Missing content uses `<span className="ph">`, styled as in the mockup (yellow background, red dashed outline).
- A production build (`next build` with `VERCEL_ENV=production`) fails if any page still renders an element with class `ph`. The check runs as a postbuild script that scans the `.next` HTML output.
- Preview builds only print warnings.

## 10. Accessibility

- A "Skip to content" link appears first in the tab order.
- Every interactive element can be reached with the keyboard and has a visible focus ring (3px, blue).
- Touch targets are at least 44×44px.
- Text contrast is at least 4.5:1, checked by axe in E2E.
- Under `prefers-reduced-motion: reduce`:
  - Transitions and animations are removed.
  - Confetti does not fire. The button label still changes.
- All images need alt text. Decorative shapes use `aria-hidden`.

## 11. SEO and sharing

- `metadata` is set per page: title, description and canonical URL.
- OG images are generated with `next/og` in the paper and sticker style.
  - Home: the name plus "UX/UI Designer who builds".
  - Case study: the title plus its tags.
- `sitemap.xml` lists the home page and every case study.

## 12. Testing

**Vitest** covers `lib/projects.ts`:

- It parses valid frontmatter.
- It throws on a missing required field and names the file and the field.
- It sorts projects by `order`.
- It computes `readTime` correctly.
- It merges timeline rows and sorts them by year.

**Playwright** runs one smoke flow at 390px and 1280px wide:

- Open `/`, run an axe check, open the first case study, run an axe check, then go back home.
- Open the mobile menu.
- Toggle the Design/Code switch and check that the name changes.

Dragging and animation are checked by hand, not by automated tests.

CI uses Vercel's build. Running the tests in GitHub Actions is optional in v1.

- A push to `main` deploys to production. Each PR gets a preview URL.
